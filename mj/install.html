build.sh

Install

mj builds from source. There is no binary release; clone the repository and run the build script.

Requirements

  • Linux, x86-64
  • a C compiler (the build script drives it)
  • for C/C++/Odin interop examples, the relevant toolchain on your PATH

Build

git clone https://github.com/h-sys-2025/mj.git
cd mj
./build.sh
# or, directly with gcc:
gcc -O3 -o build/mj mj.c stdlib/builtins/builtins.c -I. -lm -ldl -lpthread

Run a script

./build/mj examples/curriculum/01_values.mj

Start with the curriculum in order; see the Learn page.

REPL

Run ./build/mj with no file to get a small REPL. Expressions auto-print.

./build/mj
> #help
  #help / ?       this message
  #quit / exit    leave
  #clear          clear function session buffer
> 2 + 2
4

Package manager -- mjpm

Temporary glue for now. A permanent package manager, written in mj itself, is planned.

./mjpm.sh list
./mjpm.sh init demo && cd demo && ../tools/mjpm.sh add math && ../tools/mjpm.sh run

Set MJ_HOME to the mj install root so vendor packages resolve globally.

Inspecting bytecode

# pretty-print compiled bytecode, including nested functions
./build/mj --disasm path/to/script.mj

# inspect a shipped .bbw bundle, plus a raw hex dump
./build/mj --disasm path/to/script.bbw
./build/mj --dump-bbw path/to/script.bbw   # same

Runtime flags and environment

Flag / variableEffect
--no-gcdisable the mark-sweep collector, for maximum determinism
--ownershipexperimental borrow-check mode, off by default, not fully enforced
--disasm / --dump-bbwprint bytecode instead of running it
MJ_HOMEinstall root, used to resolve vendor:* imports
MJ_DUMP=1dump bytecode after the optimizer runs

Embedding and interop

mj exposes a C / C++ / Odin ABI through mj_api.h, with cstruct_* helpers and cbind for calling into native code. See stdlib/extern_c/ for the shims, and examples/interop/ and examples/embed/ for worked demos, including a Pong game driven through SDL2.
